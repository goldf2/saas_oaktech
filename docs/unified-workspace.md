# 统一商城工作台（DASH-01）

> 后续DASH-02（0.1.34）已将下述软件目录与商品管理继续合并为同一个商品列表，工作台仅保留商品和账号支持两项。管理员在同一卡片中浏览/下载/管理，普通用户仍只见公开数据。最新入口及验收以[单一商品列表](unified-product-list.md)为准；下文保留0.1.33历史设计。

## 用户要求与范围

合并Dashboard与商品后台，不再出现两个平级入口。统一地址为 `/dashboard`；按已验证账号的服务器权限显示内容，不建立另一套登录或授予角色。与PUB-01的商品/软件独立发布及0.1.32紧凑界面一同集成，不能回退任何一边。

## 操作方式

- 管理员打开工作台，默认直接显示商品管理、真实目录数量、资料草稿与版本草稿，可搜索、筛选、新建或进入商品编辑。
- 软件目录显示已公开商品，不把公开目录当作已购买软件；管理员和普通用户都可访问。
- 账号与支持保留账号信息、当前商城权限和支持入口。邮箱账号可使用既有改密入口；Casdoor账号继续由统一身份服务管理密码。
- 未登录访问工作台仍需登录；普通用户即使手填 `?view=products` 也不能获取管理表单或草稿。独立Server Action/API仍执行原有权限检查。
- 原来的Dashboard没有真实订单/许可证查询，只有固定0值；本次不把它们作为真实购买统计继续展示，不新建订单系统或宣称已实现许可证功能。

## 路由与兼容

`/dashboard` 是唯一工作台入口。管理员默认产品管理，普通用户默认公开软件目录。

| 路径 | 行为 |
|---|---|
| `/dashboard?view=products` | 管理员商品列表；无管理权限显示说明 |
| `/dashboard?view=library` | 公开软件目录 |
| `/dashboard?view=account` | 账号与支持 |
| `/admin`、`/admin/products`、`/admin/software` | 原服务器授权后转入工作台，保留有效搜索与状态筛选 |
| `/admin/products/new`、`/admin/products/[slug]` | 现有商品编辑深链接保留，返回工作台而不是另一套后台 |
| `/admin/releases?release=...` | 仍按实际版本归属转到商品内版本，不移动制品路径 |

桌面和移动导航都只有一个“工作台/Workspace”入口；编辑页继续提供返回商品管理。底层文件下载、签名、更新清单、认证配置、用户角色均不在本任务修改范围。

## 与独立发布的关系

商品资料保存与公开不发布软件。软件版本保存与公开不保存或消费商品介绍草稿。无安装包可先上架商品；后来发布软件时开启已有商品的下载入口。两种发布确认、并发指纹和预览分别处理；软件预览只使用线上商品资料，不把未发布文案展示为本次公开内容。

## 代码与验证

共享列表：`components/admin/product-management.tsx`；它独立执行服务器权限判断再读取私有目录。导航策略：`lib/store/workspace-navigation.ts`，仅负责导航，不用于替代授权。工作台：`app/dashboard/page.tsx`。

`npm run test:workspace-ui` 使用隔离的本地服务器、临时目录和仅被该测试服务器接受的合成会话，分别测试匿名/普通/管理员，检查草稿隔离、上传拒绝、查询参数伪造、旧链接、搜索、手机及深色模式。不会读取真实密码或写正式商城数据。

集成还必须运行 `npm test`、`npm run typecheck`、`npm run build`、`npm run test:publication-ui`、`npm run test:compact-ui`、`npm run test:store-ui`、`npm run test:release-ui`、`npm run test:video-ui`。测试、提交、远端推送、CI及公网状态各自单独记录，本文件不代表生产验收已经完成。

本地超级管理员、商品用途分类/多平台发布和GitHub主动同步仍是独立任务，本次不将它们标为完成。
