# 商品编辑页重排（LAYOUT-01）

## 目标与边界

用户在OpenPlay实际编辑页反馈图文、视频和发布流程混乱，要求整页重新排版。此改版整合本地PUB-02发布澄清检查点，保留商品资料和软件版本的独立保存、校验、确认与发布，不修改正式商品或自动发布生产草稿。

截图可证实的阻塞是视频标题为空且资料处于待发布状态；原校验要求标题，但旧表单没有明显的必填说明。本轮没有取得生产发布审计记录，不据此断言用户以前是否点击过发布。

## 页面结构

顶部单独标明“线上介绍”和“本次资料”，不再把商品是否上架、软件有无版本、本次资料是否发布混成一句。正式版/测试版字段改称“展示标签”，明确它不是本次发布状态。

固定工具栏内放三组分区和保存草稿、预览、发布商品资料。主操作与页签采用不同视觉权重；切换分区时将内容放在固定栏下方，避免之前的滚动位置遮挡操作。底部保留资料保存/发布按钮。

桌面左栏编辑商品名称、类别、简介、详情、平台与可选英文；右栏管理图标、封面及截图缩略图。手机按阅读顺序排列，保持可读字号，不通过整页缩放换取紧凑。

视频采用链接优先的紧凑卡片：主链接、标题和备用来源在左，可选封面在右。自定义来源名称折叠，标题缺失有输入框标记及文字说明。视频排序、删除、来源排序、封面上传沿用原逻辑。

## 发布含义

保存草稿不更新公开商品。准备发布商品资料会保存当前修改并进入核对，仍需明确确认才公开；纯预览不保存。核对区域显示图文变更、线上/本次视频数量、缺项定位和独立英文说明提醒。成功后提供中英文商品页入口。

没有软件包也可以发布商品介绍。发布软件版本不会保存或公开商品介绍草稿。视频标题/封面自动抓取、GitHub主动同步、多平台版本模型和本地超级管理员不在本次交付范围。

## 代码结构与验证

`components/admin/product-details-editor.tsx`只负责受控表单布局，不增加持久化逻辑。`product-workspace.tsx`仍拥有编辑状态和原服务动作；`product-video-editor.tsx`维护原视频结构。

运行 `npm run test:editor-layout-ui` 验证与用户截图一致的空标题场景、精确定位、明确确认后发布、纯预览不保存、真实图片上传、备用来源，以及320/390/1024/1440px布局。另保留商品、独立发布、视频、上传、语言、权限和紧凑度回归。

第一轮发现固定栏与保留滚动位置会遮住自动点击目标，修复分区滚动，并在测试中等待实际卡片/模式转换；对于指定移除来源按钮，测试先验证点击点未被覆盖，再点击并核对来源数量。没有放宽业务校验或删除失败断言。1024×768保存按钮曾超出视口5px，通过减少页头8px间距修复，控件字号/高度不变。
