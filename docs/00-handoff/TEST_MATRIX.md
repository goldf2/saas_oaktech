# 权限改造验收矩阵

版本1.0.0；以下ADM用例是**新增功能的待执行验收要求**，不是现有63项测试的通过结果。执行后将脱敏证据写入任务账本；测试文件未创建时标记planned，不生成空文件冒充覆盖。

## 测试层级与环境

- U：纯策略/配置单元测试。
- I：真实事务数据库集成测试，至少两个独立进程，不能用同进程mock代替跨容器互斥。
- B：隔离浏览器，测试身份提供方或明确标注的合成会话。
- S/P：预生产/生产真实正常登录，操作者授权后执行。合成会话不能计为真实账号通过。

候选测试文件：`tests/admin-bootstrap.test.ts`、`admin-roles.test.ts`、`admin-migration.test.ts`、`admin-integration.test.ts`、`scripts/verify-admin-ui.mjs`（均待实现）。重复执行必须使用隔离库/installation；测试角色、秘密、账号不得写入生产或仓库。

## 完成判定

ADM-12完成要求相关U/I/B用例有可复运行命令和报告；S/P仍独立保留为未验收。ADM-13/14必须由真实身份流程执行，不得用自行签发的测试Cookie顶替。外部身份服务无法确认、授权数据库未配置或维护窗口未确认，要写明具体阻塞和解除条件。

每份报告至少记录：任务ID、测试用例ID、时间与时区、目标commit、环境、命令/操作、预期与实际、退出码/HTTP结果、数据前后计数、清理或回滚、限制。不将原始身份凭证或敏感页面截图入Git。

现有63项基线测试的重新执行见 [基线证据](evidence/2026-09-16-baseline.json)；它们不能替代这里尚待实现的40条验收场景。
