# 项目简报：OakTech 软件商城

仓库：`goldf2/saas_oaktech`；站点：`oaktechz.com`。主目录为Mac上的 `/Volumes/project/项目/saas_oaktech`，但本套文档全部提供可移植的仓库相对路径。旧 `oaktools-platform` 已封存，不在其上继续开发。

## 业务边界

商品管理负责名称、分类、双语介绍、图标、封面和公开状态；软件版本管理负责版本/渠道/草稿、制品、签名与校验；公开拉取下载只服务已公开且合格的字节。商品已出现不等于软件包已发布，网页可下载也不等于原生客户端升级通过。

Auth工具 `open-play` 与缠论工具 `chanxu-tradingview` 是独立商品，素材、分类、平台、版本和下载入口不能混用。首页/个人中心应读取实际公开目录，不再叠加静态种子冒充生产上架。

## 认证与权限方向

复用现有Casdoor/OIDC登录，应用超管不是Casdoor全局管理员。用户明确采用[容器化初始化标准](../standards/CT-ADMIN-001-v1.0.0.md)：部署时一次性凭据绑定首位超管，其余管理员由后台授予/撤销，角色与初始化状态持久化。账户按已验证issuer+subject识别，不依赖邮箱/显示名。

身份平台与商城的已确认数据最小化边界保持不变，不复制身份密码和完整档案，不强制其他工具共享商城账号。现有Supabase/Creem遗留业务不在本次权限计划中迁移。

## 工程边界

Next.js App Router、TypeScript、React、NextAuth；具体版本以package-lock与实际安装为准。商品与制品元数据目前保存在 `RELEASE_STORAGE_ROOT/catalog.json`，文件和历史更新源在持久卷。该JSON写队列目前是单进程边界，不当作跨容器权限事务。

机器发布身份只导入/上传草稿，不管理人类角色、不最终公开版本。公开文件访问不强依赖身份服务。首次超管认领必须使用真实正常会话，不为解决权限问题伪造生产登录。

## 当前迭代

本迭代首要工作是超管初始化、角色管理及旧白名单迁移。技术实现、文档完成、线上版本与真实账号认领必须分别记录。详细分解见[开发方案](DEVELOPMENT_PLAN.md)，下一动作以[接续单](HANDOFF.md)为准。
